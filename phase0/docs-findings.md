## 3. Hook capability matrix

The full list is `PLUGIN_HOOK_NAMES` in `src/plugins/hook-types.ts:98-139`. There are 40 hooks.

**Kinds** (`docs/plugins/hooks/reference.md:22-29`):
- **Modify**: sequential; results merge.
- **Gate**: sequential; a block stops the rest.
- **Claim**: the first `handled: true` wins.
- **Observe**: concurrent; return values ignored; may be fire-and-forget.
- **Sync**: synchronous; promises are ignored.

**Default timeouts:** `src/plugins/hooks.ts:89-117`.

**Gating column:**
- **CA**: `plugins.entries.<id>.hooks.allowConversationAccess: true` (non-bundled plugins).
- **PI**: blocked by `hooks.allowPromptInjection: false`.

## 5. Plan changes suggested

1. **Owner-only `/guard` commands (§4.6).** `requireAuth: true` only checks the channel allowlist, and external plugins never get `senderIsOwner` in a command ctx. Register loosening commands with `requiredScopes: ["operator.admin"]`: on chat surfaces this admits only owners (`plugin-command-execution.ts:162-173`). Or compare `ctx.senderId` against `commands.ownerAllowFrom` from `api.config`. Verify on WhatsApp.
2. **Ask means block in autonomous runs (§5.8, §5.9).** OpenClaw rejects plugin approvals when the run trigger isn't `"user"` ("Plugin approval unavailable"). So Balanced "ask" in cron and heartbeat runs becomes a block. Make that explicit (block, plus queue an owner notification) instead of relying on the host's failure text. The tool ctx has no `trigger`; treat a missing `ctx.requester` as autonomous, which the plan already does. A Guard `ask` with no route also blocks; set `timeoutReason`.
3. **Parameter rewrite race (§5.2, §5.10).** Every `before_tool_call` handler sees the *original* params, and the *last* returned `params` wins. A lower-priority plugin can therefore replace the params the Guard evaluated. Fixes:
   - Register the Guard's `before_tool_call` at a very low priority so it runs last.
   - **Always** return `params` equal to exactly what it evaluated.
   - Re-check in `after_tool_call` (`event.params` includes adjustments) to log mismatches.
   - Alternatively, use `api.registerTrustedToolPolicy`. The plan says external plugins can't use it; that's wrong. Installed plugins can, if explicitly enabled and declaring `contracts.trustedToolPolicies`. Trusted policies run before ordinary hooks, and an ordinary hook that changes params after a trusted approval is blocked unless it gets its own approval.
4. **Owner identity in `message_received` (§5.4, §4.1).** The event has no `senderIsOwner` and no forward flag. Two consequences:
   - Get owner-typed status by correlating `message_received.ctx.runId` / `sessionKey` with the later `before_tool_call.ctx.requester.senderIsOwner`, or by matching `senderId` against the configured owner IDs.
   - Forwarded content can't be detected from hook metadata on any channel. Keep the "long pasted block" heuristic, treat `replyToBody` as `owner_forwarded`, and treat every `media[]` item as `owner_forwarded`.
5. **Approvals in self-chat (§5.9).** WhatsApp filters gateway echoes by message ID (20 min) before both `/approve` parsing and reaction approvals. The echo concern narrows to:
   - sends outside the gateway socket: `browser` on web.whatsapp.com, another linked device, scripts run with `exec`;
   - **`message` `react` with 👍/👎 on the approval prompt.**

   Add these to the outbound command-echo block: block `message.react` whose target is a pending approval prompt, and block `browser` navigation to `web.whatsapp.com` / `web.telegram.org`. Keep the runtime test.
6. **Tool registry (§5.5).**
   - Rename `cron` to `automations` and key on normalized names.
   - `exec`: use `workdir`, not `cwd`.
   - `apply_patch`: parse `input`.
   - `gateway`: only config reads and `update.run`.
   - Add `openclaw` and `plugins` (config/install), `conversations_send` / `conversations_turn`, `personal_instructions` (persistence_write), `process` (code), `nodes`, and `skill_workshop`.
   - `message`: `target` is optional (current conversation); include `media`/`attachments`/`buffer` as outbound content and `presentation` command buttons.
   - `web_fetch` temp-file spill paths must inherit `web`.
   - `memory_search` with `corpus:"sessions"` adds `inter_session` and private labels.
7. **`before_install` has no session ctx.** Block tainted installs at `before_tool_call` on `plugins.install`, `skill_workshop`, `openclaw`, `gateway.update.run`, and `exec` (`openclaw plugins|skills ...`). Use `before_install` only as an audit and backstop.
8. **Bootstrap labels (§5.11).** `HEARTBEAT.md` and `TOOLS.md` are gone. Watch `AGENTS.md`, `SOUL.md`, `IDENTITY.md`, `USER.md` (plus `users/*/USER.md`), `BOOTSTRAP.md`, `MEMORY.md`, skills directories, `personal_instructions` (database), and the heartbeat monitor scratch (database, written through `automations` or monitors).
9. **Deadlines (§5.12).**
   - Keep the 200 ms internal deadline. Note that the Codex native relay budget is 10 s.
   - The effective host timeout can be read from `api.config.plugins.entries[id].hooks`, but it may be stale after hot reload.
   - `onResolution` is fire-and-forget: persist `allow-always` rules idempotently, without assuming they are awaited before the tool runs.
10. **Outbound rewrite surfaces (§5.10).** Defang in `before_tool_call` (`message` params). Also hook:
    - `reply_payload_sending`, for normal assistant replies, which are themselves outbound in group chats;
    - `message_sending`, as a backstop.

    Both delivery hooks fail **open** on error or timeout, so they can't be the only enforcement. Link previews are channel-level config only (Discord and Slack off by default). Recommend config in the setup docs instead of per-message suppression.
11. **Unexpected availability.** `model_call_started` and `before_compaction` are not conversation-gated:
    - `model_call_started`'s agent ctx can carry `trigger`, `jobId`, and `inputProvenance`. Record them per `runId` to classify run triggers without `allowConversationAccess`. Verify at runtime.
    - `before_compaction` carries `messages?`.
12. **Storage (§6).** Use `api.runtime.state.openKeyedStore` and blob stores (SQLite, per plugin, survive restarts) instead of a private `node:sqlite` file. The deprecated `openSyncKeyedStore` fits synchronous `tool_result_persist`. Use `resolveStateDir()` for the JSONL audit log. Node ≥24.22.1.
13. **Double approval (§5.9, Q16).** Host exec approvals (`tools.exec.mode` `ask`/`auto`, session `guarded`/`workspace`) and `openclaw`-delegate approvals run after the Guard. When `api.config.tools.exec.mode` means the host will prompt anyway, have the Guard prefer `block` or `allow` for `exec` over its own `ask`. Otherwise include the Guard's reason in the block text. The per-session mode can't be observed.
14. **Testing (§8, §9).** Use `models.providers.<id>` with `api:"openai-completions"`, or the repo's `mock-openai` QA lane, plus the `qa-channel` plugin, for deterministic integration runs.
